# [1주차] 컴퓨터의 큰 그림: 폰 노이만 구조

## ☕ 바리스타 비유 1탄: 폰 노이만 구조란?

- 실제 의미: "명령어(Code)와 데이터(Data)를 모두 메인 메모리(RAM)에 적재하고, CPU가 메모리 주소를 순차적으로 읽어 들여 연산을 수행하는 '프로그램 내장 방식'의 컴퓨터 아키텍처”
- 비유: 만능 기계(CPU)를 하나 둔 다음, **'레시피(프로그램 명령어)'와 '재료(데이터)'를 모두 앞쪽 작업대(RAM) 위에 올려두고** 기계가 레시피를 순서대로 읽으면서 만들게 하자!

### 3대 핵심 부품

1. **보조기억장치 (SSD/HDD) = 뒷방 창고**
    - 📖 **실제 의미:** 전원이 차단되어도 데이터가 영구적으로 보존되는 비휘발성 대용량 저장 매체. 접근 지연 시간(Latency)이 밀리초~마이크로초 단위로 CPU 대비 압도적으로 느리다.
    - ☕ **비유:** 대량의 원두와 우유를 전기가 끊겨도 보관할 수 있지만, 창고까지 다녀오는 데 시간이 아주 오래 걸린다.
    - 게임 설치 파일, 엑셀 파일 등이 저장된 곳

2. **메인 메모리 (RAM) = 바리스타 바로 앞의 바(Bar) 작업대**
    - 📖 **실제 의미:** CPU가 당장 실행할 프로그램의 기계어와 데이터를 임시로 적재하는 고속 작업 공간. 전원이 꺼지면 데이터가 소멸하는 휘발성(Volatile) 메모리.
    - ☕ **비유:** 퇴근 시 전원을 끄면 싹 치워지지만, 손만 뻗으면 재료를 즉각 집어 들 수 있다. 창고에서 오늘 당장 쓸 재료와 레시피만 올려두는 좁은 작업대
    - 지금 실행 중인 프로그래밍이 올라가는 곳

3. **CPU = 1초에 수십억 번 손을 움직이는 초인적인 바리스타**
    - 📖 **실제 의미:** 메모리에서 명령어를 인출(Fetch)하고 해석하여 논리/산술 연산을 수행하는 컴퓨터의 두뇌. 처리 속도가 기가헤르츠(GHz) 단위로 극도로 빠르다.
    - ☕ **비유:** 연산 속도가 너무 빨라 창고(SSD)를 직접 다녀올 시간이 없으며, 오직 작업대(RAM) 위에 올라온 재료만 보고 작업한다.

이 컨베이어 벨트를 타고 재료가 오가는 속도조차 답답해진 바리스타 위해, 캐시(Cache)라는 공간 만들어 보자!


### 프로그램 실행의 본질

바리스타(CPU)는 0.000001초 만에 커피를 만드는데 창고(SSD)에서 우유를 가져오는 데 1시간이 걸린다고 가정해 보자. 바리스타가 창고를 직접 왔다 갔다 하면 일하는 시간보다 대기하는 시간이 훨씬 길어진다.

👉 바탕화면의 아이콘을 실행(더블 클릭)하면, 창고(SSD)에 있던 파일들을 바리스타 앞 작업대(RAM)로 쫙 끌어다 놓는다. 이것을 **"메모리에 로드(Load)한다"** 고 부른다.



### 유일한 단점 (병목 현상)

- **폰 노이만 병목(Bottleneck):** 바리스타(CPU)의 손놀림은 엄청 빠른데, 작업대(RAM)에서 레시피와 재료를 가져오는 통로의 속도가 그걸 따라가지 못한다. (바리스타가 아무리 일을 잘해도 재료가 손에 안 쥐어지면 그 순간 동안 놀아야 함)
- 이를 해결하기 위해 CPU 내부에 **‘캐시(Cache)’라는 초소형 개인 냉장고**를 추가로 두게 된다!



### 시스템 버스(System Bus)

바리스타(CPU)와 작업대(RAM) 사이에는 보이지 않는 3개의 컨베이어 벨트(버스)가 돌아가고 있다.

1. **주소 버스 (Address): CPU가 읽거나 쓸 메모리 번지를 전송**
    - 바리스타가 "작업대 3번 구역에 있는 거 가져와!"라고 위치를 지시하는 벨트
2. **제어 버스 (Control): 읽기/쓰기 등의 제어 신호를 전송**
    - 바리스타가 "가져와(Read)!" 혹은 "거기 올려놔(Write)!"라고 명령을 내리는 벨트
3. **데이터 버스 (Data): 실제 명령어와 데이터가 이동**
    - 실제 레시피나 우유(데이터)가 이동하는 벨트

## ☕ 바리스타 비유 2탄: 캐시(Cache) 메모리의 세계

컨베이어 벨트를 타고 재료가 오가는 속도조차 답답해진 바리스타를 위해 도입한 **‘초고속 임시 보관소’**이다. 물리적으로 CPU 칩셋 안에 내장되어 있다.

### 캐시의 3계급 (L1, L2, L3)

바리스타와의 거리에 따라 3단계로 나눈다. (숫자가 작을수록 가깝고, 빠르고, 비싸고, 용량이 적음)

- **L1 캐시 (바리스타의 앞치마 주머니):** 작업대(RAM)까지 갈 필요 없이 손만 넣으면(1ns) 바로 나온다.
    - 효율을 극대화하기 위해 '레시피 전용 주머니(Instruction)'와 '재료 전용 주머니(Data)'로 나뉜다. (하버드 구조의 흔적)
- **L2 캐시 (커피 머신 바로 위 선반):** 앞치마 주머니(L1)보다는 크고, 살짝 손을 뻗어야 하는 공간.
- **L3 캐시 (바리스타 공용 미니 냉장고):** 현대의 멀티 코어(여러 바리스타) 환경에서 동선 한가운데 두고 공유하는 공용 냉장고. 작업대(RAM)보다는 훨씬 가깝다.

### 캐시의 핵심 원리: 지역성 (Locality)

수많은 재료 중 캐시에 뭘 챙겨둬야 할까? 캐시는 '지역성'이라는 2가지 꼼수로 데이터를 예측한다.

1. **시간적 지역성 (Temporal Locality):** "방금 쓴 시럽은 1분 뒤에 또 쓸 확률이 높다.”
    - for문, while문 같은 반복문이 빠른 이유. 방금 실행한 코드는 주머니에 넣어두고 계속 꺼내 쓴다.
2. **공간적 지역성 (Spatial Locality):** "바닐라 시럽을 썼으면, 그 옆에 있는 헤이즐넛 시럽도 곧 쓸 확률이 높다.”
    - 캐시는 RAM에서 데이터를 가져올 때 1개만 가져오지 않고, **그 주변 데이터를 뭉텅이(Block)로 한 번에 쓸어 담아** 주머니에 넣는다. (배열이 리스트보다 빠른 이유!)

### 캐시 히트(Hit)와 미스(Miss)

- **Cache Hit (적중):** 주머니(L1)에 손을 넣었는데 마침 필요한 바닐라 시럽이 있다. 0.1초 만에 커피 완성! (성능 최고)
- **Cache Miss (실패):** 주머니에 시럽이 없다. 선반(L2), 공용 냉장고(L3)를 거쳐 결국 저 멀리 작업대(RAM)까지 걸어가서 가져와야 한다. (성능 저하)

## ☕ 바리스타 비유 3탄: 자료구조와 캐시 (메모리 배치 싸움)

자료구조를 고른다는 것은 결국 **"캐시가 싹쓸이하기 좋게 재료를 어떻게 줄 세울 것인가"**를 결정하는 것이다. (전제: 캐시는 주변 재료를 한 뭉텅이(Cache Line)로 푹 떠서 가져오는 습성이 있다.)

### 1. Java/C언어의 순수 배열 (Array) = "계란 판"

- **구조:** 실제 데이터가 메모리 공간에 **다닥다닥 연속해서** 붙어있다.
- **결과:** 바리스타가 한 뭉텅이를 퍼오면 다음 순서의 데이터들이 전부 앞치마 주머니에 들어온다. 작업대에 다시 갈 필요 없이 **Cache Hit**가 빵빵 터지며 최고 속도로 연산한다.

### 2. 연결 리스트 (Linked List) = "보물찾기 쪽지"

- **구조:** 실제 데이터가 사방에 무작위로 흩어져 있고, 다음 데이터의 위치(포인터)만 가리킨다.
- **결과:** 한 뭉텅이를 퍼와도 다음 데이터가 아니라 쓸모없는 쓰레기 데이터만 딸려 온다. 다음 데이터를 찾을 때마다 작업대까지 다시 걸어가야 하는 **Cache Miss**가 연속으로 발생해 속도가 느리다.

### 3. 파이썬 리스트 (Python List) = "재료가 아니라 '쪽지'를 모아둔 철"

- **구조:** 파이썬 리스트 안에는 진짜 재료가 아니라, **데이터가 있는 위치(주소)가 적힌 '쪽지(포인터)'들만** 나란히 줄 서 있다. (진짜 데이터는 창고 구석구석 흩어짐)
- **왜 인덱스마다 다른 타입(int, string 등)을 섞어 쓸 수 있을까?**
    - 똑같은 규격의 '쪽지'만 꽂아두면 되니까 내용물이 무엇이든 상관없기 때문이다.
- **성능의 대가 (반쪽짜리 캐시 히트):**
    - 쪽지들을 한 번에 쓸어 담아오는 건 빠르지만, 결국 연산을 하려면 쪽지에 적힌 주소를 보고 **매번 저 멀리 흩어진 진짜 데이터를 찾아 뛰어나가야 하므로 Cache Miss가 폭발**한다.
    - 이 때문에 인공지능/데이터 분석에서는 파이썬 기본 리스트 대신, 내부적으로 C언어 배열을 써서 캐시 효율을 극대화한 **NumPy(넘파이)** 라이브러리를 필수로 사용한다.
